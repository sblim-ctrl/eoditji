## 1. 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | Vite + React + TypeScript + Tailwind + shadcn/ui | 참고한 ai-assistant-card 컴포넌트를 그대로 쓸 수 있음. 정적 배포 |
| 배포 | Vercel (정적) | 저장소를 연결하면 바로 배포됨 |
| 로그인 | Supabase Auth: 이메일 6자리 코드(OTP, 메일에 링크도 함께), Google | 이메일은 따로 등록할 앱이 없음. 구글은 익숙함. 휴대폰 메일 앱의 링크는 다른 브라우저로 열릴 수 있어 코드 입력을 기본으로 함 |
| DB | Supabase Postgres + RLS | 그룹 단위 권한을 DB 규칙으로 강제 |
| 사진 | Supabase Storage 비공개 버킷 `photos` | 서명 URL로만 보여 줌 |
| 서버 함수 | Supabase Edge Functions (Deno): `recognize`, `search` | OpenAI 키를 브라우저에 두지 않기 위해 |
| LLM | OpenAI Responses API, 구조화 출력(JSON schema strict), `store: false`. 인식 `gpt-6.1-terra`(비교 `gpt-6-luna`), 검색 `gpt-6-luna` | 모델 이름은 환경변수로 바꿀 수 있게. 선택 근거와 비용은 PRD 05 "모델과 비용" |

## 2. 아키텍처

```
브라우저 (Vite + React, Vercel)
  ├─ supabase-js ──> Auth (이메일 OTP, Google)
  ├─ supabase-js ──> Postgres (RLS)        places / items / item_labels / events
  ├─ supabase-js ──> Storage 'photos'      썸네일 업로드, 서명 URL
  ├─ match.ts (0단계 검색, 브라우저에서 실행)
  └─ fetch(JWT) ──> Edge Functions
                     ├─ recognize: 사진(base64) → OpenAI 비전 → 초안(물건, 박스, 다른 이름, 질문, 추천 질문)
                     └─ search:    0단계에서 못 찾은 질문만 → 사용자 JWT로 후보 조회(pg_trgm) → 작은 LLM → 검증 → 로그
                                    OPENAI_API_KEY는 Supabase secrets에만 있음
```

**정해 둔 것**

- **사진 흐름**
  - 초안 단계에서는 1400px JPEG를 base64로 `recognize`에 보내기만 하고 저장하지 않습니다.
  - 사용자가 저장을 누르면 640px 썸네일만 Storage에 올립니다. 버려진 사진이 쌓이지 않게 하려는 것입니다.
- **저장**: RPC `save_place(group_id, area, name, items jsonb)` 한 번으로 칸과 물건을 한 트랜잭션에 넣습니다 (`0005_save_place.sql`, security invoker라 RLS가 그대로 걸림).
  - 내가 볼 수 있는 같은 공간·같은 이름의 칸은 새 기록으로 바꿉니다(프로토타입과 같은 규칙). `place_id`는 그대로 두고 물건을 통째로 바꿉니다.
  - 사진 순서 (D2에서 정함): 썸네일 경로에 `place_id`가 들어가므로 `save_place`가 먼저입니다. `save_place` → 썸네일을 `photos/{group_id}/{place_id}/{ts}.jpg`에 올리기 → `photo_path` 갱신 → 같은 칸을 다시 찍었으면 예전 썸네일 지우기
  - 올리기가 실패하면 사진 없는 칸이 남으므로 "사진 다시 올리기"를 안내합니다.
  - 칸을 지울 때는 사진 파일을 먼저 지웁니다. 칸이 없어지면 그 사진을 지울 권한도 없어지기 때문입니다.
- **함수의 로그인 확인** (D2에서 바뀜): 플랫폼 `verify_jwt`는 새 API 키와 맞지 않아 끄고, 함수 안에서 `getUser`로 확인합니다 (`_shared/http.ts`).
  - `search`의 후보 조회는 사용자 JWT로 부르는 RPC `search_candidates`입니다 (`0004_search_candidates.sql`). RLS가 걸려 볼 수 있는 칸의 물건만 후보가 됩니다.
- **프롬프트**: `supabase/functions/_shared/prompts.ts` 한 곳에 둡니다.
  - `PROMPT_VERSION` 상수를 모든 로그에 남깁니다.
  - 대화 상대별 말투 조각도 여기에 둡니다. 화면 문구는 `src/lib/personas.ts`에 있습니다.
- **같은 코드 공유**: 검색 핵심(`search.ts`), 인식 핵심(`recognize.ts`), 정규화·일치(`match.ts`), 검증(`validate.ts`)은 `_shared/`에 둡니다.
  - Edge Function, 평가 스크립트, 브라우저(Vite 별칭 `@shared`)가 같은 파일을 씁니다.
  - 그래서 평가 때는 DB·로그인 없이 30건을 돌릴 수 있습니다.
- **음성**: 배포된 HTTPS에서는 Web Speech API(`ko-KR`)를 씁니다.
  - 지원하지 않는 브라우저에서는 키보드 받아쓰기를 안내합니다. 프로토타입과 같은 방식입니다.

## 3. 모바일과 카메라

**반응형 (모바일 우선)**

- **화면**: 720px 한 줄 대화 기둥을 씁니다.
  - 확인할 폭: 360 / 390 / 430px와 데스크톱
- **높이와 안전 영역**: `100dvh`와 `env(safe-area-inset-*)`를 씁니다.
- **입력창**: 키보드가 올라와도 가려지지 않게 합니다.
  - viewport meta에 `interactive-widget=resizes-content`를 넣고, iOS는 `visualViewport`로 보정합니다.
  - iOS Safari는 키보드가 올라오면 보이는 영역을 아래로 밀어 내립니다. 그래서 높이(`vv.height`)뿐 아니라 시작 위치(`vv.pageTop`)만큼 앱을 옮기고, 대화를 맨 아래로 붙입니다 (D2 실기기에서 발견).
- **터치와 글자**: 터치 영역은 44px 이상, 입력 글자는 16px 이상(iOS 자동 확대 방지)입니다.
- **기억해 둔 곳**: 모바일은 아래에서 올라오는 시트, 데스크톱은 오른쪽 시트로 보여 줍니다(shadcn `Sheet`).
  - 공간별로 묶어 보여 줍니다. 공간과 그 안의 칸은 최근에 찍은 순서이고, '공간 없음'은 맨 아래에 둡니다.
  - 공간 고르기: 사진과 칸 이름을 받은 뒤 전에 쓴 공간을 칩으로 보여 줍니다. 칩을 누르거나, 새로 적거나, 건너뜁니다. 인식 결과를 기다리는 동안 물어서 기록 시간이 늘지 않게 합니다.
  - 칸 카드와 검색 답에는 "책상 · 왼쪽 첫째 서랍"처럼 공간을 앞에 붙입니다.
  - 칸 상세에서 공간 바꾸기: 저장할 때와 같은 칩으로 고릅니다. 옮길 공간에 같은 이름의 칸이 있으면 unique에 걸리므로 이름을 바꾸라고 안내합니다.
  - 공간 이름은 앞뒤 공백을 지우고 저장합니다("책상"과 "책상 "이 따로 묶이지 않게).

**카메라**

| | A. 파일 입력 + `capture` (P0) | B. 앱 안 카메라 `getUserMedia` (P1) |
|---|---|---|
| 동작 | `<input type="file" accept="image/*" capture="environment">`로 기본 카메라를 바로 엶 | 페이지 안 카메라 화면에서 찍음 |
| 권한 | 웹 권한 창 없음 | HTTPS 필수, 권한 창, 거절 가능 |
| 화질 | 휴대폰 카메라 그대로 | 영상 프레임이라 보통 더 낮음 |
| 더 할 수 있는 것 | — | 촬영 가이드 겹쳐 보이기, 연속 촬영, 손전등 |
| 손전등 | 기본 카메라 플래시 | Android Chrome은 `torch` 제약으로 가능. iOS Safari는 실기기 확인 후, 안 되면 버튼 숨김 |

- **P0 버튼 두 개**: "카메라로 찍기"(`capture="environment"`)와 "앨범에서 고르기"(`capture` 없음)
- **P1 권한 처리**
  - 권한은 버튼을 눌렀을 때 짧은 설명을 보여 준 뒤 묻습니다.
  - `navigator.permissions.query({name: 'camera'})`가 되는 브라우저에서는 상태를 미리 확인합니다.
  - `NotAllowedError`이면 설정 방법을 안내하고 A로 대체합니다.
- **사진 처리** (`src/lib/photo.ts`, 프로토타입의 `readPhoto`/`draw`)
  - 캔버스로 다시 JPEG로 저장하므로 EXIF(GPS)가 지워집니다.
  - 방향은 브라우저가 바로잡고, iOS HEIC도 JPEG가 됩니다.
  - 예외: iPhone Safari 카메라로 위에서 평평하게 찍으면 사진이 180° 뒤집혀 저장될 때가 있습니다. 자동으로 알아낼 수 없어서, 첨부 미리보기에 "사진 돌리기"(시계 방향 90°) 버튼을 둡니다. 인식 전에 돌리므로 박스 좌표를 따로 바꾸지 않습니다 (D2 실기기에서 발견).
  - 이미지가 아니거나 너무 큰 파일은 거절합니다.

## 4. AI가 본 위치와 라벨

- **박스 좌표**: 인식 출력에서 sure / guess / hidden을 `{name, box, aliases}` 배열로 받습니다.
  - `box`는 `[x1, y1, x2, y2]`, 0~1000 정규화 정수이고, 모르면 `null`입니다.
  - 정규화 좌표라서 썸네일에도 그대로 겹쳐 그릴 수 있습니다.
- **좌표 검증**: `validate.ts`에서 바로잡거나 `null`로 바꿉니다.
  - 범위를 벗어난 값은 0~1000으로 자릅니다.
  - x1과 x2, y1과 y2가 뒤집혀 있으면 바꿉니다.
  - 넓이가 0이면 `null`로 둡니다.
- **표시 방식은 D1 스파이크로 정합니다.** 사진 3장으로 확인합니다.

  | 결과 | 판정 기준 (박스가 그 물건을 대체로 덮는 비율) | 표시 |
  |---|---|---|
  | 정확함 | 60% 이상 | 테두리 박스 |
  | 대충 맞음 | 60% 미만이지만, 나머지 박스도 대부분 그 물건 근처에 있음 | '대략 위치'(흐린 스포트라이트) |
  | 거의 틀림 | 그 외 | 3×3 칸 중 하나를 고르게 하는 출력으로 대체 |

  - 판정은 박스를 사진 위에 그려 눈으로 합니다(10/30 확정).
  - D3에 정답 박스와의 IoU ≥ 0.5 비율로 다시 재고, PRD 03 기준(60%)으로 최종 확정합니다.
  - **D1 결과 (10/31, `eval/spike-box.ts`)**: 눈으로 판정한 적중은 terra 약 64%(39개 중 25개), luna 약 50%(32개 중 16개)입니다. 그래서 **terra + 테두리 박스**로 정했습니다.
    - 위에서 똑바로 찍은 사진 2장에서는 terra가 대부분 맞혔습니다. 비스듬히 찍은 투명 정리함 사진 1장은 두 모델 모두 박스와 이름이 거의 틀렸습니다.
    - 그래서 D2 후보로 카메라 화면에 "위에서 똑바로 찍어 주세요" 안내를 둡니다.
    - luna는 박스를 너무 크게 잡거나 이름과 박스가 뒤바뀐 경우가 많았습니다.

- **컴포넌트**: 초안 카드, 칸 상세, 검색 결과가 같은 컴포넌트를 씁니다.
  - `PhotoBoxes`: 보기 전용. % 단위로 절대 위치를 잡은 div로 그립니다. 칩을 누르면 강조되고, 사진을 누르면 해당 칩이 선택됩니다.
  - `PhotoBoxEditor`: `react-image-crop`로 박스 그리기·옮기기·크기 조절을 합니다. 터치를 지원합니다.
  - `ItemActions`: 맞아 / 위치 고치기 / 이름 고치기 / 빼기 / + 물건 추가(사진에서 짚기 선택)
- **라벨**: 행동마다 `item_labels`에 한 줄을 추가합니다. 지우지 않습니다.
  - `items`는 현재 상태만 갖습니다.
  - 이름 고치기는 aliases 학습에도 쓰입니다(5절).

## 5. 검색 비용 전략

**원칙**: 질문할 때 하던 추론을 저장할 때로 옮깁니다. 기록은 드물고 검색은 자주 일어나기 때문입니다.

```
[저장할 때] 인식 호출 한 번으로 물건마다 aliases 3~6개(다른 이름·줄임말·용도)를 함께 생성
            직접 적은 물건은 저장할 때 작은 텍스트 호출 한 번으로 묶어서 생성
[검색할 때]
 0단계 브라우저: match.ts가 질문을 정규화(조사·띄어쓰기 제거) → 이름·aliases와 정확히 하나만 일치하면 바로 답
 1단계 서버:     pg_trgm으로 search_text가 비슷한 후보 상위 20개 (+ 0단계에서 여러 개 걸린 것)
 2단계 작은 LLM: 후보 안에서만 고름 → {intent, itemIds[], confidence}
                 itemIds는 이번 후보 id를 enum으로 둔 JSON 스키마로 제한
 3단계 (P1):     confidence가 low인데 후보가 있으면 큰 모델로 한 번 더
[답 문장]        대화 상대 템플릿(personas.ts의 foundAt 등)이 만듦
```

**쓰면서 배우기**

| 신호 | 처리 |
|---|---|
| LLM 단계로 찾은 결과에 "찾았어!" | 그 질문을 정규화한 표현을 해당 물건 aliases에 추가 (`learn_alias`) |
| 이름 고치기 | 고친 이름을 aliases에 반영 |
| 0단계 결과에 "거기 없던데?" | 일치에 쓰인 alias를 지움 |

**그 밖의 절감 방법**

| 방법 | 내용 |
|---|---|
| 모델 나누기 | `OPENAI_SEARCH_MODEL=gpt-6-luna`, `OPENAI_VISION_MODEL=gpt-6.1-terra`. 인식도 luna로 바꿀지 평가에서 비교 (기준은 PRD 05) |
| 추론 강도 | 기본 `medium`은 추론 토큰이 출력 요금으로 청구됨. 검색 `none`, 인식 `low`로 시작해 정확도와 함께 비교 |
| 출력 줄이기 | id만 받고 문장은 템플릿이 만듦 |
| 인식 이미지 크기 | 768 / 1024 / 1400px로 평가 사진 10장을 돌려 인식률과 비용을 비교 |
| 프롬프트 캐시 | GPT-5.6 이후 규칙: 1,024토큰 이상 같은 앞부분만 캐시됨. 쓰기는 입력가의 1.25배, 읽기는 0.1배(terra·sol은 0.05배), 기본 유지 30분<br>후보 20개 검색은 1,024토큰 미만이라 해당 없음<br>v1 기준선, 그리고 서랍을 연달아 찍는 인식(지시문이 1,024토큰을 넘을 때)에서만 의미가 있음<br>지시문 → 기록 → 질문 순서로 앞부분을 고정 |
| 결과 캐시 (P1) | `groups.inventory_version`이 같으면 같은 질문의 결과를 재사용 |
| 평가 실행 | Flex 처리(표준가의 50%)로 돌림 |

**위험**

| 위험 | 대응 |
|---|---|
| aliases가 넓어 여러 물건에 걸림 | 0단계는 정확히 하나만 일치할 때만 답함 |
| 0단계 오답 | "거기 없던데?"로 alias를 지움. 평가에서 0단계 오답률을 따로 잼 |
| 후보에서 정답이 빠짐 | 1단계 recall을 따로 잼. 낮으면 후보 수를 늘리거나 임베딩(P1)을 앞당김 |

`shortcut:` 주석: P0의 후보 추리기는 pg_trgm만 씁니다. 동의어 recall이 부족하면 pgvector 임베딩을 합칩니다.

## 6. 데이터 모델 (`supabase/migrations/0001_init.sql`)

처음부터 그룹 단위로 만들어서, P1 그룹 기능을 붙일 때 마이그레이션이 필요 없습니다.

```sql
profiles(id uuid pk references auth.users, display_name text,
         persona text check (persona in ('mom','jarvis')) default 'mom',
         allow_training boolean default false)

groups(id uuid pk, name text, created_by uuid, created_at timestamptz,
       inventory_version int default 0)                       -- places·items가 바뀌면 트리거로 +1

group_members(group_id uuid, user_id uuid, role text check (role in ('owner','member')),
              joined_at timestamptz, primary key (group_id, user_id))

group_invites(code text pk, group_id uuid, created_by uuid, expires_at timestamptz)   -- P1

places(id uuid pk, group_id uuid,
       area text not null default '',                         -- 칸이 속한 공간(방·가구). ''이면 '공간 없음' (null이면 unique가 안 걸려서)
       name text, photo_path text,
       created_by uuid,                                       -- 공유 스위치를 바꿀 수 있는 사람
       visibility text check (visibility in ('private','group')) default 'group',
       captured_by uuid, captured_at timestamptz,             -- 마지막으로 찍은 사람과 시각
       unique (group_id, area, name))

items(id uuid pk, place_id uuid references places on delete cascade, group_id uuid,
      name text, level text check (level in ('sure','guess','hidden','told')),
      inside text, source text check (source in ('ai','user')),
      box int[] check (box is null or array_length(box, 1) = 4),
      box_source text check (box_source in ('ai','user')),
      aliases text[] default '{}',
      search_text text generated always as (name || ' ' || array_to_string(aliases, ' ')) stored)
-- index: gin (search_text gin_trgm_ops)
-- P1: embedding vector(1536)  (text-embedding-3-small 기본 차원, 붙일 때 다시 확인)

item_labels(id bigint generated always as identity pk, place_id uuid, group_id uuid, item_id uuid null,
            photo_path text,
            action text check (action in ('confirm','move','rename','reject','add','draw')),
            ai_name text, ai_box int[], user_name text, user_box int[],
            model text, prompt_version text, created_by uuid, created_at timestamptz)

events(id bigint generated always as identity pk, user_id uuid, group_id uuid,
       name text, props jsonb, created_at timestamptz)
```

**트리거**
- `auth.users`에 사용자가 생기면 다음 셋을 만듭니다.
  - `profiles` 행
  - 그룹 "내 집"
  - 그 그룹의 owner 멤버십
- places·items가 바뀌면 `groups.inventory_version`을 1 올립니다.
- `places.visibility` 변경은 `created_by = auth.uid()`일 때만 허용합니다(BEFORE UPDATE).

**RLS**

| 대상 | 규칙 |
|---|---|
| 판별 함수 | `is_member(gid)`, `can_see_place(pid)` (둘 다 security definer, stable). `can_see_place`는 같은 그룹 멤버이고, 칸이 공유 중이거나 내가 기록한 칸일 때 true |
| places, items | `can_see_place`일 때만 읽기·쓰기. 검색 함수도 사용자 JWT로 조회하므로, 남이 끈 칸은 후보에서 빠짐 |
| groups | 멤버만 읽기, owner만 수정·삭제 |
| group_members | 직접 추가 금지, RPC `join_group(code)`로만 |
| item_labels | `created_by = auth.uid()`이고 `can_see_place(place_id)`일 때만 추가. 읽기 정책 없음 |
| events | `user_id = auth.uid()`일 때만 추가. 읽기 정책 없음 |
| Storage `photos` | 경로는 `{group_id}/{place_id}/{ts}.jpg`. 올리기는 첫 폴더가 내 그룹일 때만, 읽기는 `can_see_place(place_id)`일 때만 |

**D1 구현에서 위 설계와 달라진 것** (`supabase/migrations/`)
- 0001
  - `places`의 `group_id`와 `created_by`는 바꿀 수 없게 막았습니다. 남이 공유한 칸의 작성자를 자기로 바꾼 뒤 비공개로 돌려 숨기는 것을 막기 위해서입니다.
  - `places` 정책은 `can_see_place` 대신 행의 값으로 판정합니다.
  - `items`는 `(place_id, group_id)` 복합 외래키로 칸과 같은 그룹만 허용합니다.
  - 검색어 열은 immutable 함수로 감쌌습니다(`array_to_string`은 stable이라 생성 열에 쓸 수 없음).
- 0002: 새 테이블 자동 노출을 꺼서 `service_role`에도 권한이 없었습니다. 그래서 따로 권한을 줬습니다.
- 0003: 칸 보호 트리거가 계정 삭제 때의 `on delete set null`까지 막고 있었습니다. 로그인 사용자의 요청만 막도록 고쳤습니다.
- 위 셋 모두 `scripts/rls-check.ts`에서 확인합니다(19개 항목).

**남용 방지**
- 함수가 오늘 날짜의 `events`를 세어 한도를 넘으면 429를 돌려줍니다.
  - 인식 20회/일, 검색 100회/일
- 화면에는 대화 상대 말투로 안내합니다.
- OpenAI 대시보드에 월 예산 한도를 겁니다.
